# ROBOCON 2027 机械新人训练营

组长统一录入版，适合刚入学的大一机械新人。使用 Sites 托管、ChatGPT 管理员登录、D1 数据库和 R2 文件存储。新人点开链接即可只读查看，只有平台所有者可以管理。

## 查看与管理权限

新人直接打开首页链接，无需登录 ChatGPT 或关联账号。可查看姓名、班级、考核要求、提交状态及已确认分数。公开数据不含学号、备注、附件、建议分、内部评语、评分证据和账号邮箱。

账号关联入口及登录记录面板已停用，旧关联接口返回 410，不再写入新账号记录。已有数据库记录保留，相关读取与解除接口仍只对组长开放。

组长点击「组长管理」或打开 `/manage`，通过 ChatGPT 登录后管理。管理页面、Workspace 接口、文件上传/下载、MCP 数据及评分写入均在服务端核对 Sites 身份。运行配置 `PLATFORM_OWNER_USER_ID` 固定为本站所有者的 Sites 用户 ID（不同于账户 ID），未配置则拒绝管理和公开读取。不得依赖第一个访客、邮箱输入框或浏览器按钮隐藏来判断权限。更换所有者时须显式更新此配置。

本机预览在忽略的 `.dev.vars` 中设置 `PLATFORM_OWNER_USER_ID=local_seedy`；线上值通过 Sites 运行配置设置，不写入源码。Sites 链接访问策略为 public。所有持链接者均可只读查看，管理页面、Workspace、原文件和 GPT 评分接口继续限制为组长身份。

## 使用顺序

平台只保留「新人名单」「最终考核」，默认进入最终考核。

1. 在「新人名单」添加或编辑姓名、班级、学号，直接保存。支持搜索和名单导出。
2. 在「最终考核」点击对应新人的「查看 / 上传」，上传三视图建模、测绘、零件装配材料。
3. 考核完成后由 GPT 提供建议分，组长复核确认。
4. 右上角「备份」导出或恢复 JSON 数据。原文件须另行下载保管。

日常学习、日常作业不再展示或参与评分。历史记录、原文件和资料链接继续保存在数据库及完整备份里。旧考核配置首次读取时迁移为三项 20/35/45；原评分保留为待复核。之后修改分值不会再次重置。

首次名单导入仍由私有运行配置 INITIAL_STUDENT_ROSTER 控制，批次标记防止重复导入。

## 最终考核与 GPT 评分

「最终考核」包含三视图建模 20 分、测绘 35 分、零件装配 45 分。各项先按 0–100 分评价，再按当前分值加权。「分值与要求」可以修改分值、截止日期、提交要求和评分标准，三项分值合计必须为 100。培训任务的质量/理解/修改评分仍独立保留。

三项最终考核由组长收齐后上传。每人每项一条记录，补交和修改使用「编辑」。日常记录及附件不会送入本次综合评分。需要上传题目、模型、截图、手机实测尺寸记录、装配配合及干涉检查证据。手机按简化外形评价，不要求内部结构或复杂曲面；装配按预期运动检查，不要求全部锁死。

平台提供带用户身份校验的 `POST /mcp`，通过 Sites 配置 `capabilities: ["mcp"]` 创建平台插件。首次需在插件安装界面连接（或 Plugins > Personal > Created by you 中找到本平台并 Install/Connect）。考核完成后，在已连接插件的 GPT 对话中要求读取材料、按当前标准综合评分，并把建议分与依据保存回平台。没有另外调用模型 API，没有自动生成虚构分数。

工具为 `list_assessment_students`、`get_assessment_materials`、`read_assessment_file` 和 `save_assessment_review`。它们只允许组长访问自己的数据。PNG/JPEG 返回实际图片，PDF 返回嵌入资源，单附件读取上限 8 MB；客户端若无法读取 PDF 应标为待核查。SW/CAD/压缩包不做解析，也不声称检查尺寸、特征树、重建或干涉。由组长在提交材料的说明及检查反馈中记录现场结果。

GPT 结果必须有每项分数或证据不足时的 null、评分理由、证据清单、待核查内容，以及综合评语。建议分在页面复核后由组长确认；GPT 不可确认或覆盖已确认成绩。缺少必考材料或分数时不计算总分。材料或分值变化会使原评分失效；保存评分使用材料指纹及数据库版本检查，阻止过期结果覆盖新数据。原始建议仍可查看。

另可导出评分材料 JSON（元数据、要求、检查记录和结果模板，不含附件内容）、导入符合模板的建议评分 JSON，或导出最终成绩 CSV。

## 历史培训任务记录

旧培训任务保留完成质量 40%、理解程度 40%、修改能力 20%；各项输入 0–100 分。标记「已完成」必须进度 100% 且三项评分完整。平均成绩只计已完成任务。整体任务进度按所有新人和所有任务计算。

## 数据保护

服务端根据 Sites 注入的用户身份读写独立记录；拒绝未登录、非法输入、跨域写入和过期版本覆盖。数据库保留服务端版本号；多窗口发生冲突时导出当前修改后刷新再编辑。

测试数据与本机预览数据库不会发布到线上。CSV 做了 UTF-8 BOM、引号转义及公式注入防护。

## 开发

项目使用 Vinext / React / TypeScript / Cloudflare D1 / Drizzle。保留 .openai/hosting.json 中的项目标识。按 Sites 技能的发布流程执行依赖安装、迁移生成、构建、源码同步与部署。

- npm run dev：本机开发预览
- npm run db:generate：生成数据库迁移
- npm run build：构建 Worker
- node scripts/verify-readonly.mjs：匿名只读、字段筛选、确认成绩、管理权限拒绝与手机页面检查（verify-members.mjs 为别名）
- node scripts/verify-platform.mjs：本机浏览器及数据库集成测试
- node scripts/verify-homework.mjs：最终材料上传失败重试、下载字节、文件归属及手机表单测试
- node scripts/verify-assessment.mjs：最终材料、MCP 身份与读写、加权评分、确认与过期保护及手机页面测试
- node scripts/verify-roster.mjs：名单合并、去重、导入防重复及手机名单测试（接口部分需要本机测试名单配置）

浏览器测试脚本通过 scripts/browser-runtime.mjs 自动查找 Playwright 与 Chromium 内核浏览器，不再写死某一台机器的路径。运行前需先安装：

```
npm i -D playwright
npx playwright install chromium
```

若已在本机其他位置安装 Playwright，可用环境变量指定，无需重复下载：

- PLAYWRIGHT_MODULE：含 playwright 包的目录
- BROWSER_EXECUTABLE：msedge/chrome 可执行文件路径（默认自动探测常见安装位置）
- VERIFY_BASE_URL：被测站点地址，默认 http://127.0.0.1:5173

缺少依赖时脚本会以退出码 69 结束并打印安装指引。这些脚本需要先运行 npm run dev，并会在执行过程中写入及还原测试数据。

Windows 安装与构建时须注意中文路径和 npm 命令包装器兼容性。项目内 .sites-runtime 是忽略的本机工具与运行状态，不上传。
